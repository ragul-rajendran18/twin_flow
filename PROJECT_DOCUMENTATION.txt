A3. WORKING MODULES (FEATURES)
--------------------------------------------------------------------------------

1) AUTHENTICATION & AUTHORIZATION
   - Public registration. New accounts are ALWAYS created with the operator
     role (privilege escalation is blocked at the API level).
   - Login returns a short-lived bearer JWT (default 30 min, configurable).
   - GET /me returns the signed-in user profile.
   - Change password (requires current password; min 12 chars).
   - Role guard: require_role(ADMIN) / require_role(ADMIN, MANAGER).
   - 401 responses carry WWW-Authenticate: Bearer.

2) USER MANAGEMENT (admin only)
   - List users (paginated), get one, update name/email.
   - Activate / deactivate a user.
   - Change a user's role (admin | manager | operator).
   - Safety rule: the LAST active administrator cannot be demoted or
     deactivated (HTTP 409 "last_active_admin").

3) AISLE MANAGEMENT
   - Read: any authenticated user (list, filter by zone/active, detail,
     per-aisle event history).
   - Write: admin only (create, patch). Duplicate aisle codes -> 409.

4) EVENT INGESTION
   - Single event POST and batch POST (max batch size configurable,
     default 50). Available to admin and manager.
   - Validates ranges (occupancy 0-100, conveyor_load 0-100, non-negative
     counts), unknown aisle -> 404, duplicate event_id -> 409 / counted in
     batch results.

5) WAREHOUSE MONITORING (dashboard APIs)
   - /overview : total/active aisles, normal/moderate/high counts,
     active alert count, average occupancy, total AGVs, total queue
     length, last event timestamp. Aisles without events count as normal.
   - /aisles   : latest event + latest prediction (congestion level) per aisle.
   - /events   : paginated telemetry with filters (aisle_code, source,
     start_time, end_time).

6) ML PREDICTIONS
   - /run            (admin/manager): runs the trained model over the latest
     event of every active aisle (or one aisle). Creates predictions and
     auto-raises or auto-updates alerts. Returns model version, counts.
   - /latest         : newest prediction per aisle (optionally filtered).
   - /history        : paginated prediction history.
   - /{prediction_id}: single prediction with joined event payload.
   - Model output: congestion_probability, congestion_level
     (NORMAL/MODERATE/HIGH via 0.40 / 0.70 thresholds), bottleneck_detected,
     predicted_queue_length, predicted_delay_minutes, recommendation text,
     model_version.
   - Returns 503 if the model artifact has not been trained yet.

7) ALERTS
   - List with filters (status, severity, alert_type, aisle_code, time range).
   - GET /active : all ACTIVE alerts sorted HIGH > MEDIUM > LOW, newest first.
   - PATCH /{id}/resolve (admin/manager): resolves the alert and stamps
     resolved_at; returns {message, alert_id, status}. Resolving a
     non-active alert is tolerated and reported in the message.
   - Alerts auto-resolve when a newer prediction for that aisle is clean.

8) SIMULATION (synthetic data, admin/manager writes)
   - /seed     : creates the 8 standard aisles (AISLE_A..AISLE_H across
     ZONE_1..ZONE_4). Re-running is safe (existing aisles skipped).
     Optionally generates a historical event batch.
   - /generate : pushes N synthetic events (max 500 default) through the
     real ingestion service.
   - /step     : advances every active aisle (or a listed subset) by one
     interval.
   - Scenarios: normal, moderate, high_congestion, bottleneck, mixed.
   - /status (any user): seeded/active aisle counts, total events, latest
     timestamp, supported scenarios, max batch limit.

9) HEALTH
   - GET /health     : liveness.
   - GET /health/db  : database connectivity.

10) CROSS-CUTTING
    - CORS from env (CORS_ORIGINS), credentials allowed.
    - Global exception handlers: validation 422, SQLAlchemy 500, generic 500.
    - Pagination helper returns {total, page, page_size, items}.

B3. WORKING MODULES (PAGES / FEATURES)
--------------------------------------------------------------------------------

1) LOGIN (/login)
   - Email + password, stores JWT in localStorage (twinflow.token),
     redirects to the dashboard. Backend-error messages are surfaced.

2) REGISTER (/register)
   - Full name, email, password (min 12 chars), and a Role select with a
     "Select role..." placeholder. Operator is the only self-serve option;
     Manager/Admin options are visible but disabled (assigned by an admin).
     On success the account is logged in automatically.

3) LAYOUT / SHELL
   - Sidebar: Dashboard, Aisles, Events, Predictions, Alerts, Simulation,
     Users (admin only), Profile. Role-filtered.
   - Topbar: user name + role badge + Sign out.
   - Footer dot: live /health check showing "API online / offline".

4) DASHBOARD (/)
   - 8 KPI stat cards: total aisles, normal, moderate, high congestion,
     active alerts, average occupancy, AGVs in motion, total queue.
   - Aisle status table (occupancy bar, AGVs, queue, congestion badge,
     last update) with row-click navigation to the aisle detail.
   - Active alerts panel and latest predictions panel.
   - Auto-refresh every 30 s + manual Refresh; "Run predictions" button
     for admin/manager.

5) AISLES (/aisles)
   - Paginated table with zone and active/inactive filters.
   - Admin: "New aisle" form and per-row "Edit" (code is immutable on edit).
   - Click a row -> aisle detail.

6) AISLE DETAIL (/aisles/:id)
   - Status cards: occupancy, AGV count, queue length, order volume,
     conveyor load, congestion level.
   - Paginated event history table for that aisle.

7) EVENTS (/events)
   - Paginated warehouse telemetry with filters: aisle code, source,
     from/to datetime. Shows occupancy, AGVs, queue, orders, conveyor,
     source badge, timestamp.

8) PREDICTIONS (/predictions)
   - Tabs: "Latest per aisle" and "History" (paginated).
   - Filters: congestion level, aisle code.
   - "Run predictions" button (admin/manager) reports model version and
     how many predictions/alerts were created or updated.

9) ALERTS (/alerts)
   - Tabs: "Active" (severity-sorted) and "All" (paginated, filterable by
     status, severity, type).
   - "Resolve" button (admin/manager) on active alerts; shows the API
     confirmation message.

10) SIMULATION (/simulation)  (admin/manager)
    - Status cards: seeded aisles, active aisles, total events, latest event.
    - Step 1: Seed aisles (optional historical events, scenario select).
    - Step 2: Generate N events (bounded by the backend max).
    - Step 3: Advance one step for all active aisles.

11) USERS (/users)  (admin only)
    - Paginated user table.
    - Inline edit of name/email, role dropdown (admin/manager/operator),
      enable/disable toggle.
    - The signed-in admin cannot disable their own account; the backend
      additionally protects the last active admin.

12) PROFILE (/profile)
    - Account summary card + change-password form (current, new, confirm;
      min 12 chars, must differ from current).

--------------------------------------------------------------------------------
B4. CONNECTION TO THE BACKEND
--------------------------------------------------------------------------------
Development (default)
  - Browser calls same-origin paths (/api/v1/..., /health).
  - Vite dev server proxies them to VITE_BACKEND_URL
    (default http://127.0.0.1:8000). No CORS involved.

Production / direct mode
  - Set VITE_API_BASE_URL to the full backend URL (e.g.
    http://127.0.0.1:8000) in twinflow/.env; the axios baseURL becomes
    "<VITE_API_BASE_URL>/api/v1" and the browser hits the backend directly.
    The backend must allow the frontend origin in CORS_ORIGINS.

Security model
  - Token stored in localStorage, attached as "Authorization: Bearer <jwt>".
  - Any 401 clears the token and redirects the user to /login.
  - Route guards: GuestOnly (/login, /register), Protected (everything
    under the Layout), AdminOnly (/users).
